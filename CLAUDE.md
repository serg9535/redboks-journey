# Redbok's Journey — конвенции проекта

Обучающая игра для детей ~5 лет: изучение английских слов через exploration + пошаговый бой,
в духе Shattered Pixel Dungeon (тайловая карта, но без permadeath — см. ниже).

## Стек

Vite + Phaser 3 (не 4 — API v3 стабильнее и предсказуемее). Чистый JS, без TypeScript, без React.

## Команды

Выполняются из этой директории (`game/`):

- `npm run dev` — dev-сервер (`vite --host 0.0.0.0`, чтобы был доступен с телефона в той же сети).
- `npm run build` — прод-сборка в `dist/` (использует `vite.config.js`: `base` = `/redboks-journey/`
  при `GITHUB_PAGES=true`, иначе `/` — см. деплой ниже).
- `npm run preview` — локальный просмотр прод-сборки.

Автотестов нет. Проверка — вручную в браузере (`npm run dev`) после изменений.

Деплой — автоматический через `.github/workflows/deploy-pages.yml` на push в `master`
(GitHub Pages). Ручного деплой-шага не требуется.

## Структура

- `src/data/vocab.js` — словарь по биомам: `{sprite, word, ru}[]` на биом. Единственное место, где
  привязывается спрайт монстра к английскому слову (+ русский перевод для опционального тултипа).
- `src/data/proceduralMap.js` — генератор карт (комнаты+коридоры, BFS-связность гарантирована),
  детерминированный по числовому seed (mulberry32 PRNG).
- `src/data/maps.js` — по seed на биом (`BIOME_SEEDS`) генерирует `MAPS[biome]` через
  `proceduralMap.js`; карта одного биома стабильна между заходами (seed не меняется), но разная
  между биомами. Индекс `monsterTiles[i]` соответствует `BIOMES[biome].words[i]`. Мирные локации
  (деревня, поляна) — РУЧНЫЕ карты (`VILLAGE_LAYOUT`/`MEADOW_LAYOUT`) — они про диалоги, не про
  бой, процедурность тут не нужна. У каждой мирной локации свой `npcs` (список из `npcs.js`) и
  опционально `portals` (тайл-переход в другую мирную локацию, см. `attemptMove` в WorldScene) —
  `PEACEFUL_LOCATIONS` перечисляет их все разом, чтобы сцене не нужно было хардкодить имена.
- `src/data/npcs.js` — жители мирных локаций: `{sprite, name, lines[]}`, отдельный массив на
  локацию (`VILLAGE_NPCS`, `MEADOW_NPCS`, ...) + `ALL_NPCS` для препрелоада в BootScene. `lines` —
  обычные русские строки с английскими словами ЗАГЛАВНЫМИ + переводом в скобках прямо в тексте
  (без отдельного rich-text движка — Phaser.Text не умеет разноцветный текст внутри одной строки
  без BBCode-плагина).
- `src/data/settings.js` — настройки игрока в localStorage (пока только показ RU-перевода).
- `src/scenes/WorldScene.js` — пошаговое перемещение по сетке (клавиатура/D-pad/тап-путь через BFS),
  пинч-зум камеры (следует за игроком), туман войны, HUD, bump-to-battle, экран «биом пройден»,
  bump-to-dialogue для NPC, bump-to-portal переход между мирными локациями (визуально — 🌸 на
  тайле). Мир и UI — на разных Phaser-камерах (`worldLayer`/`uiLayer`,
  см. `cameras.main.ignore()`/`uiCamera.ignore()`), иначе HUD/D-pad зумились бы вместе с картой.
- `src/scenes/BattleScene.js` — MVP боя: слово + 3 варианта, HP монстра/игрока, опциональный RU-перевод.
- `public/assets/sprites/` — нарезанные PNG (прозрачный фон) + `manifest.json` с bbox.
- `public/assets/backgrounds/` — фоновые текстуры биомов.
- `scripts/slice_sprites.py` — нарезка сырых грид-листов (Stable Diffusion/OpenAI) на кадры.
  Сырые листы кладутся в `raw/sprites/` (в репозиторий не коммитятся, см. `.gitignore`).
- `scripts/generate_openai.py` — генерация ассетов через OpenAI Images API (нужен `OPENAI_API_KEY`
  в `.env`, платно). Требует незаблокированный биллинг на platform.openai.com.
- `scripts/generate_asset.py` — генерация ассетов через Gemini API (`imagen-3.0-generate-002`,
  нужен `GEMINI_API_KEY` в `.env` или переменной окружения). Использование:
  `python scripts/generate_asset.py --prompt "<описание>" --out "public/assets/sprites/<file>.png" --ratio 1:1`.
  **На 2026-08-09 не работает** — free tier на проекте с ключом даёт `limit: 0` для
  `generate_content_free_tier_requests` (та же проблема, что и с OpenAI — нужен привязанный
  биллинг-аккаунт в Google Cloud, подписка Google AI Pro на квоту API не влияет). Не вызывать
  автоматически, пока это не решено — сначала проверить, включён ли биллинг. См. также
  `scripts/gemini_compare.py` (сравнение стиля Gemini vs LoRA, тот же барьер).
- `scripts/generate_comfyui.py` — генерация через локальный ComfyUI (`http://127.0.0.1:8188`,
  см. ниже), по одному персонажу за раз + LoraLoader с `rbkstyle.safetensors`.
- `scripts/prepare_lora_dataset.py` — собирает датасет для тренировки стилевой LoRA из уже
  нарезанных спрайтов (`public/assets/sprites/` + `raw/sprites/refgrid/`), кладёт в
  `raw/lora_dataset/10_rbkstyle/` с подписями (caption).
- `scripts/crop_transparent.py` — вырезает фон у генераций "один персонаж на изображении"
  (`generate_comfyui.py`/`generate_meadow.py` и т.п.), превращая в плотно обрезанный прозрачный
  PNG. Флуд-филл от края с допуском на соседний пиксель (а не фиксированный порог от цвета угла) —
  нужен, потому что "плоский" фон в промпте всё равно содержит пиксель-дизеринг, который фиксированный
  порог либо не вырезает целиком (тёмный фон остаётся видимым по краям), либо, если персонаж тёмный
  и близок по цвету к фону (пример: чёрная пчела на тёмно-синем фоне), протекает внутрь персонажа.
  Само по себе не универсально на 100% — при большом контрасте между частями персонажа иногда нужно
  подобрать `step_tol` руками (см. `scripts/generate_meadow.py` для примера ручного фолбэка).

## Как добавить новый биом

1. Сгенерировать/получить лист монстров + фон биома (см. «Локальная генерация через ComfyUI+LoRA» ниже).
2. `raw/sprites/<sheet>.png` → добавить в `scripts/slice_sprites.py` (словарь `sheets`) → запустить скрипт.
   Либо, если генерировали по одному персонажу (`generate_comfyui.py`), кадры уже отдельные —
   прогнать через ту же логику вырезания фона (см. пример в истории/`generate_comfyui.py`).
3. Добавить запись в `BIOME_SEEDS` (`src/data/maps.js`) — любое число, отличное от других биомов;
   карта сгенерируется сама (см. цикл по `Object.keys(BIOMES)` там же). Без seed сработает
   fallback-хэш от ключа биома, но лучше задать явно для стабильности.
4. Добавить запись в `BIOMES` (`src/data/vocab.js`) — слова в том же порядке, что появятся монстры
   (`monsterTiles` процедурной карты назначаются по одному на комнату в порядке генерации).

Логику сцен трогать не нужно — она полностью управляется данными.

## Как добавить NPC в мирную локацию (деревня/поляна/...)

1. Сгенерировать портрет (см. `scripts/generate_meadow.py` как шаблон под свою локацию, или
   `generate_comfyui.py`) — трактуйте персонажа как ещё одно "милое существо", а не буквально
   человека: LoRA сильно тянет к своему датасету монстров независимо от промпта (elder/merchant/
   teacher, bee/butterfly/rabbit вышли круглыми зверушками, не людьми — это нормально и вписывается
   в мир, где Redbok тоже не человек).
2. Обрезать фон через `scripts/crop_transparent.py`, положить в `public/assets/sprites/npc_<id>.png`.
3. Добавить запись в соответствующий массив в `src/data/npcs.js` (`VILLAGE_NPCS`/`MEADOW_NPCS`/...).
4. Добавить тайл в `MAPS.<location>.npcTiles` (`src/data/maps.js`); NPC берётся из
   `map.npcs[i % map.npcs.length]` по индексу тайла.

## Как добавить новую мирную локацию (по образцу поляны)

1. Сгенерировать NPC + фон (см. выше и `scripts/generate_meadow.py`).
2. В `src/data/maps.js`: ручная раскладка `##`/`.` (как `MEADOW_LAYOUT`), `MAPS.<key> = {layout,
   playerStart, npcTiles, npcs, portals}`; `portals` — необязательно, но если локация должна быть
   достижима из игры (не только через dev-панель), нужен хотя бы один тайл-портал туда И обратно
   (см. `MAPS.village.portals`/`MAPS.meadow.portals` — переход двусторонний, каждая карта держит
   свою половину).
3. Добавить `<KEY>_INFO = {label, background}` и вписать в `PEACEFUL_LOCATIONS` — этого достаточно,
   чтобы локация появилась в dev-панели, préload'ился фон и работала кнопка "назад".
4. Логику сцен трогать не нужно — она полностью управляется данными (`PEACEFUL_LOCATIONS`,
   `map.npcs`, `map.portals`).

## Локальная генерация через ComfyUI + LoRA (Stable Diffusion)

Base SD1.5 и обычные аниме-чекпойнты (`anything-v5`) НЕ воспроизводят стиль игры сами по себе —
нужна LoRA, обученная на наших же спрайтах.

- ComfyUI portable: `C:\Users\SS\ComfyUI_windows_portable` (NVIDIA CUDA build; на старом драйвере
  падает с access violation — нужен драйвер ≥ 595.x). Запуск:
  `python_embeded\python.exe -s ComfyUI\main.py --windows-standalone-build`, порт 8188.
- Чекпойнты: `ComfyUI/models/checkpoints/anything-v5.safetensors` (+ базовый `v1-5-pruned-emaonly-fp16`).
- Обученная стилевая LoRA: `ComfyUI/models/loras/rbkstyle.safetensors` (trigger word `rbkstyle`,
  network_dim 32, 10 эпох на 75 изображениях — 45 существующих спрайтов + 30 из референс-листа
  ChatGPT). Обучалась через `sd-scripts` (kohya) — переиспользует embedded-python ComfyUI (он же
  и есть venv с рабочим torch+CUDA), доустановлены зависимости из `sd-scripts/requirements.txt`
  (без строки `-e .` — она ломает установку; `safetensors==0.4.5` пришлось ослабить до `>=`, иначе
  требует сборки из исходников через maturin).
  - **Важно**: embedded python использует `._pth`-файл, который отключает автодобавление
    директории скрипта в `sys.path` и игнорирует `PYTHONPATH`. Чтобы `sd-scripts` находил свой
    пакет `library`, нужен `.pth`-файл в `site-packages` со строкой-путём до `sd-scripts` (уже
    сделано, не трогать).
  - Рекомендуемая сила LoRA (`strength_model`/`strength_clip`) — **0.4–0.5** (см.
    `scripts/lora_sweep.py` и `raw/sprites/comparison_grid.png` — сравнение силы 0.4/0.55/0.7/0.85
    на одинаковых seed+промптах). На 0.7 (старый дефолт) и особенно 0.85 в кадр начинают лезть
    лишние объекты не из промпта (кустики, кактусы на фоне) — прямое нарушение negative-промпта
    ("no complex background, no scenery"); на 0.4-0.55 фон остаётся чистым, а фирменный стиль
    (обводка, чиби-пропорции, глаза) держится одинаково сильно на всех уровнях — деградирует
    именно предметное соответствие промпту, а не стиль. Смена сэмплера/CFG при фиксированной
    силе 0.7 проблему не решает — лишние объекты появляются независимо от сэмплера.
  - LoRA хорошо переносит СТИЛЬ, но слабо держит нетипичный для датасета контент (роботы) — нужны
    явные механические детали в промпте (`made of metal, metallic plating, mechanical joints`) и
    негативы против животных (`rabbit, bunny, animal ears, fur`), если персонаж уезжает в зверька.
  - Фоны/текстуры через LoRA — результат нестабилен (датасет почти целиком из портретов
    персонажей): для `background_robots.png` модель рисовала ещё одного персонажа вместо текстуры
    (пришлось рисовать программно, PIL), а `background_village.png` с первой попытки получился
    отличным полноценным пейзажем. Стоит попробовать один раз с промптом-описанием сцены (не
    персонажа), но держать процедурный/PIL-фон как готовый план B, если результат — снова портрет.
  - **Ракурсы, которых нет в датасете, LoRA не генерирует вообще** — не вопрос силы/промпта.
    Redbok (`redbok_00..10`) существовал только анфас; при движении вверх по карте он "шёл лицом
    к камере". Просили нарисовать вид со спины ("back view", "no face visible") на разной силе
    LoRA (0.7→0.45→0.2) и с усиленным негативом — итог всегда анфас с лицом, потому что модель
    физически не видела эту сторону персонажа на тренировке. Даже отключение LoRA (чистый
    `anything-v5`) не помогло — без стилевого лока модель просто уезжает в аниме-девочек (отсюда
    `1girl, girl, woman...` в каждом негативе по всему проекту). Рабочее решение — сгенерировать
    референс где-то ещё (у нас — вручную через ChatGPT, промт с явным "no face, back of the head
    only, viewed from behind" сработал с первого раза) и добавить его в датасет LoRA
    (`raw/lora_dataset/10_rbkstyle/redbok_back_00.*`) для дообучения — новый ракурс сам не
    появится, его нужно физически показать модели.
  - **Число в имени папки датасета — это `num_repeats`, не подсказка**: `10_rbkstyle` значит
    "10 повторов каждого изображения за эпоху", а НЕ "обучать 10 эпох". `--max_train_epochs`
    умножается поверх этого — легко случайно получить в 10 раз больше шагов, чем нужно (сам так
    ошибся: выставил `--max_train_epochs=10` поверх уже 10-кратной папки → 7600 шагов вместо 760,
    ~21 час вместо ~1.5). Для этого датасета `--max_train_epochs=1` уже даёт эффективные "10 эпох".
  - **ComfyUI и `train_network.py` конкурируют за те же 6GB VRAM** — если ComfyUI-сервер не
    остановлен перед тренировкой, шаги замедляются на порядок (наблюдал 17-90 сек/it вместо
    ожидаемых ~5 сек/it) из-за подкачки/вытеснения памяти между процессами. Останавливать ComfyUI
    перед запуском `train_network.py`, поднимать обратно только когда тренировка закончена.
  - **Одного нового примера в датасете на 76 недостаточно, чтобы модель усвоила новый ракурс.**
    Дообучил (`rbkstyle_v2.safetensors`, 760 шагов/1 эпоха, тот же датасет + 1 фото Redbok'а со
    спины) и проверил — генерация "back view" всё равно вышла анфас с лицом, ракурс не усвоился;
    вдобавок пострадал цвет/чистота фона на обычных (анфас) генерациях по сравнению с оригинальной
    `rbkstyle.safetensors`.
  - **Вторая попытка (`rbkstyle_v3.safetensors`) — результат смешанный, тоже не продакшн.** Датасет
    расширили до 86 изображений: + 3 доп. позы Redbok'а со спины (вместо одной), + 6 роботов
    (`robots_00-05` — были сгенерены давно, но забыты при первой сборке датасета — `prepare_lora_
    dataset.py` не перезапускали), + 1 референс фона леса без персонажа (все — вручную через
    ChatGPT/уже готовые файлы). 1720 шагов / 2 эпохи (~2ч16м на RTX 2060). По факту:
    - Redbok со спины — **всё ещё не получилось**, снова анфас с лицом (хотя лицо на этот раз
      получилось глючноватым — небольшой сдвиг есть, но до рабочего результата далеко), да ещё и
      обычная генерация анфас деградировала (сломались пропорции цвета, вылезла проблема с гридом
      4-в-1 вместо одного персонажа).
    - Фон (задача "нарисуй текстуру пустыни") — **не получилось**, вышел абстрактный
      геометрический паттерн, не текстура.
    - Лесное существо анфас — на удивление нормально, без регресса.
    - Робот анфас — **заметно лучше**, чем раньше: явно "механический" силуэт без ручных
      ухищрений в промпте, которые раньше были обязательны.
    **Итог: ни `rbkstyle_v2`, ни `rbkstyle_v3` не подключены нигде в проекте — используется
    оригинальная `rbkstyle.safetensors`.** Оба файла остаются на диске
    (`ComfyUI/models/loras/rbkstyle_v{2,3}.safetensors`) как эксперимент, не как кандидат на
    замену. Похоже, что заливать несколько разных новых концептов (ракурс + фон + новый тип
    контента) в один проход — плохая идея: результат нестабилен и местами регрессирует то, что уже
    работало. Если пробовать снова — по одному новому концепту за раз, с проверкой после каждого,
    а не пакетом; возможно, нужен LR ниже 1e-4 или другой network_alpha, раз добавление контента
    сдвигает баланс существующего стиля.

### КРИТИЧЕСКИЙ баг Phaser — maxParallelDownloads

`Phaser.Game` config должен явно задавать `loader: { maxParallelDownloads: 200 }` (см. `src/main.js`).
Дефолт — 32. Если суммарное число файлов в `BootScene.preload()` превышает 32, всё, что идёt
после 32-го, молча остаётся в `load.list` и НИКОГДА не грузится — без ошибки, без `loaderror`,
`totalFailed` остаётся 0. `create()` всё равно вызывается (луз-детекция «нет активных закачек»
срабатывает раньше, чем очередь реально опустошается). Раньше это не проявлялось, пока суммарное
число ассетов (фоны+спрайты+redbok-кадры) не перевалило за 32 при добавлении биома `robots`.
Если при добавлении нового биома у монстров вдруг нет текстуры без единой ошибки в консоли —
первым делом проверить этот лимит.

## Игровые решения (зафиксировано, не пересматривать без явного запроса)

- **Без permadeath.** При проигрыше боя — мягкий откат на чекпоинт карты, без потери выученных слов.
- **Мягкий туман войны**, не пугающая чернота — детская аудитория.
- **Пошаговое движение по тайлам** (клавиша = один шаг), не свободное перемещение.
- Стиль ассетов: чиби пиксель-арт, см. style-lock промт в `prompt.md` (родительская папка).
